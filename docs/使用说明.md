# StoryScienceLab 使用说明

> 面向操作者的上手指南：环境准备 → 跑通最小示例 → 全量运行 → 产出报告。
> 技术细节见《技术文档.md》。

---

## 0. 一键运行（推荐）★

**改配置 → 点 bat → 看产物**，三步：

1. 编辑根目录 `settings.json`：配置**原始小说路径**、**读取章数**、**模型**。
2. 双击 `run.bat`。
3. 产物在 `outputs/<小说名>_<日期>/` 下，双击 `index.html` 浏览。

```bash
# 等价命令行（本地 Ollama，默认，零配置）
python src/cli.py viz --backend qwen3-8b

# 云端 dots.ai（key 放 settings.json 或 --key）
python src/cli.py viz --backend dots3-note --key 你的key
```

`run.bat` 默认只跑**可视化层**（详情页 + 图谱 + 报告 + 导航页），因为抽取/LLM 直出需要跑模型、
耗时数十分钟，通常单独执行。要一键串起全流程，把 `run.bat` 里的 `viz` 换成
`extract collect mine viz` 即可（见下）。

**任务**：`extract`（抽取）· `build`（LLM 直出）· `personality`（性格六维）· `graph`（知识图谱）·
`detail`（拆书详情页）· `report`（对比报告）· `rag "问题"` · `viz`（一键生成可视化）。

**交互模式**：直接 `python src/cli.py` 进入菜单，选后端 + 选任务。

**后端预设**：见根目录 `models.json`（local=Ollama+qwen3:8b，cloud=dots.ai）。
换其他云端（DeepSeek/通义/OpenRouter…）在文件里加一组配置即可，或继续用第 4 节的环境变量方式。

## 1. 环境准备

| 依赖 | 说明 | 安装 |

## 4. 切换云端模型（dots.ai / DeepSeek / 通义…）

**默认本地 Ollama，零配置**。接任意 OpenAI 兼容云端只需设 4 个环境变量：

```bash
# Windows PowerShell
$env:LLM_BACKEND   = "openai"
$env:LLM_BASE_URL  = "https://note3-prev-api.askdiandian.com"   # dots.ai 示例
$env:LLM_API_KEY   = "你的key"
$env:LLM_AUTH_SCHEME = "apikey"     # dots.ai 用 api-key 头; DeepSeek/通义等用 bearer
$env:LLM_MODEL     = "dots3-note-prev"

python src/stage2.py --chapters 50 --all-outlines --characters --settings --summary \
    --out-dir data/llm_50/cloud_fixed
```

**各家关键配置**：

| 厂商 | LLM_BASE_URL | AUTH_SCHEME | 模型示例 |
|---|---|---|---|
| dots.ai（小红书） | `https://note3-prev-api.askdiandian.com` | `apikey` | `dots3-note-prev` |
| DeepSeek | `https://api.deepseek.com/v1` | `bearer` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `bearer` | `qwen-plus` |
| OpenRouter | `https://openrouter.ai/api/v1` | `bearer` | `deepseek/deepseek-chat` |

### ⚠️ 云端必读（血泪教训）

1. **关深度思考**：dots.ai 默认开启深度思考，且顶层 `thinking:false` **无效**，
   必须传 `chat_template_kwargs.enable_thinking:false`（客户端已内置，无需手动）。
   不关的话 token 消耗虚高 6 倍（50 章白烧 ~80,000 token）。
2. **先探针**：接新厂商前，先打一发最小请求，检查 `usage` 字段与 `reasoning_content`，
   确认思考链可关、计费口径。
3. **限流**：dots.ai RPM=60 / TPM=150 万（按 key），429 会自动退避重试 4 次；
   全量 50 章建议分批。

## 8. 知识图谱可视化（角色关系 + 设定）

```bash
# 1) 生成图谱数据（读 db + cloud_fixed 产物，构建节点/边/章节映射）
python src/export_graph.py --src cloud_fixed
#    → outputs/<小说名>_<日期>/graph_data.json (78 节点 / 218 边: 23 角色 + 55 设定, 别名归并后)

# 2) 打开图谱页面
#    outputs/<小说名>_<日期>/knowledge_graph.html（纯静态，浏览器直接打开）
```

**图谱功能**：
- 三个视图：角色关系图谱 / 设定图谱 / 全局（角色+设定）。
- 边类型：显式关系（characters.关系，橙）、同场景共现（灰）、设定 related 关联（蓝）。
- **章节筛选**：顶部 1–50 章按钮可多选（再点取消），节点/边/详情/关键事件全部随筛选联动；点「全部」恢复。
- 点击节点 → 右侧详情卡：身份/别名/首次出现章/关键事件/出现章节列表/关联跳转。
- 设定按类型着色：人物身份紫 / 概念青 / 物品橙 / 地点绿 / 组织红 / 力量蓝。

## 8.5 拆书详情页（book_detail.html）★ 核心可视化

```bash
# 一键生成并归档（含性格六维，本地模式走缓存秒过）
python src/cli.py viz --backend qwen3-8b

# 或单步：
python src/build_detail.py        # → outputs/<小说名>_<日期>/book_detail.html（自包含单文件）
python src/cli.py viz          # 生成 outputs/<小说名>_<日期>/index.html 导航页
```

**功能**（详见根 README）：
- **全局章节筛选**：搜索下拉 + 右侧章节滚动轴（50 标记点），四 Tab 全部联动；点章节轴不再强制切 Tab
- **剧情**：50 章时间轴（hover 展开事件）+ 章纲卡片三色浮点（🟢人物/🔵设定/🟠场景，点击弹详情）+ 伏笔备注
- **人物**：力导向关系图谱（悬停高亮连线、点击换画像）+ 画像（身份/弧光/关键事件/**性格六维雷达图**）
  同人重名已由 `aliases` 做确定性归并（30→23 人），雷达标签不再挤成一团
- **设定**：世界观/势力/物品 分类卡片（首见章 + 关联 + 备注）
- **文风**：词云 + 句长/标点统计 + 句式修辞 + 数据驱动结论，**支持按章筛选**（每章独立统计）

数据管道：`src/build_detail.py` 读 db（原文/场景）+ LLM 产物 → `detail_data.json` → 模板注入 HTML。
性格六维：`src/gen_personality.py` 云端分批生成（5 人/批 + 重试 + 增量缓存），支持 `--src`。

**健康检查**：`python src/check_viz.py --src cloud_fixed` —— 16 项数据/模板一致性断言，
退出码 != 0 表示有 error（书名、人物数、图谱边引用、别名泄露、perChStyle pct、标点键、
章节标题、占位符替换、自包含性等）。

## 8.6 拆书知识库（index.html）★ 新一代主入口

Stage1 跑完后自动生成（或手动 `python src/cli.py viz` 重建, **不重跑 LLM**）。
浏览器直接打开 `outputs/<小说名>_<日期>/index.html`。

### 界面速览
- **顶栏**: 全局搜索（人物/设定/台词, 回车跳第一个结果）
- **左侧目录**: 人物按整合度排序; 设定按分类分组, 组内按整合度降序
- **Infobox（右侧卡）**: 词条关键信息 + 局部关系小图（设定页）
- **内链**: 正文中蓝色词均可点击跳转对应词条

### 整合度权重（S/A/B/C 徽章）
`权重 = 暗线命中 + 场景覆盖 + 关系度 + 被结论引用` 的对数加权。
- 🟨 **S**（≥60）核心词条 / 🟦 **A**（35-60）重要 / ⬜ **B**（15-35）一般 / C（<15）折叠为"次要词条"
- 概览页「核心词条榜」= 全站权重 Top15
- 阈值换书可调: `src/index_template.html` 里 `lvlOf()`

### 通用名词筛选
侧栏「设定」区有 **【本书设定】/【含通用】** 开关（默认只看专有）。
通用词（医院/队友/S级xxx 这类放哪本小说都成立的词）灰显 + 黄点, 词条页有警示条。

### 公版词库维护（跨书共享）
词库文件: `src/generic_lexicon.json`。**pipeline 抽取时用它拦截（通用词不入图谱）, 面板用它打标**——改一份两端生效。
- 加词: 直接往 `categories` 对应分类里加
- 专有保护: 《》【】包裹的词永远视为专有
- 刻意不收: 职业名（牧师/法师）、群体词（信徒）——具体书中常有特指, 误杀代价高
- 跑新书发现漏网通用词 → 补进词库 → 后续所有书受益

### 字段来源徽章（防幻觉）
🟢 原文抽取（语录/释义/场景）· 🟡 LLM 推断（身份/履历/性格/疑点, 建议复核）· 🔵 统计聚合 · 🟣 混合。
面板零生成内容, 全部来自 stage1 JSON。

### global 通识库（默认关闭，按需加载）

拆书时**默认不使用**任何外部通识知识（保证本文事实纯净）。只有你明确知道这本书的类别时才加载：

```bash
python src/cli.py collect --genre 宫斗     # 加载"宫廷权谋"域（贵妃/选秀/内务府…）
python src/cli.py collect --genre 修仙     # 加载"修真仙侠"域（炼气/金丹/元婴…）
python src/cli.py collect --genre 诡秘     # 加载"诡秘神秘学"域（序列/魔药/扮演法…）
python src/cli.py collect                  # 不加载（默认）
```

支持的类别（35 条别名）：宫斗/宫廷/后宫 · 宅斗/种田 · 修仙/修真/仙侠 · 玄幻/斗气 · 高武 ·
系统 · 无限 · 诡秘/克苏鲁 · scp · 规则怪谈 · 洪荒 · 都市/异能 · 游戏/电竞 ·
科幻/机甲/末世 · 历史/军事 · 灵异/恐怖/盗墓 · 武侠/国术

**用途限定**：仅作补档（提示漏抽的等级档位）、分类参考、候选提示。
**铁律**：与原文冲突时**一律以本次阅读到的为准**，global 只写 `wn_*` 参考字段，不覆盖词条定义与分类。

不知道类别？先用样本词条搜一下（只判定不加载）：
`python -c "import webnovel_lexicon as W; print(W.detect_genre(['序列9','魔药','扮演法']))"`



**Q1: 为什么本地 4b 的章纲只有 48 章？**
4b 在 28/45 章偶发吐坏 JSON，`_parse_json` 救不回。换 8b 或云端可全成功。

**Q2: 为什么 settings 提取为空/很少？**
历史上 3 个 bug 已修：① 数组被截坏 ② 提示词示例被回显 ③ related 列表污染。
若仍少，是模型对设定提取保守，可换 8b/云端。

**Q3: 云端 token 为什么比本地多？**
修复深度思考后基本持平（~328 vs ~300 tok/章）。如果还多，检查：
- 是否用了旧版 llm_client（`thinking:false` 无效）
- 响应是否带 `reasoning_content`（可写探针检查）

**Q4: RAG 答案为什么带「首先，用户的问题是…」？**
小模型复述问题的固有习惯。用「结论：」开头提示词 + 输出示例压制；
本地 4b 复述最重，建议用 8b 跑问答。

**Q5: 需要 GPU 吗？**
本地推理需要（Ollama）；云端不需要。抽取 50 章约耗时数十分钟，可后台跑。

**Q6: FTS5 中文检索 0 命中？**
缺中文分词器所致，向量检索（bge-m3）正常，建议以向量为主。

**Q7: 详情页 23 人，索引页却写 30 人？**
LLM 常把同一人拆成多条（周明瑞/克莱恩·莫雷蒂、邓恩/邓恩·史密斯/马车夫）。
详情页/图谱已用 `aliases` 做确定性归并（30→23）；`personality.json` 仍按原始 30 条 key 存储，
索引页的数字从该文件动态读取。如需一致，重跑 `gen_personality.py` 后再归并即可。

**Q8: 没装 jieba 会怎样？**
词频统计自动降级为标准库 2-4 字滑窗 + 子串去重（纯 stdlib，不阻断流程），只是词云颗粒度略粗。
生产环境建议 `pip install jieba`。

## 9. 常用参数速查

| 参数 | 说明 | 默认 |
|---|---|---|
| `--chapters N` | 处理前 N 章 | 取 `settings.json` 的 `chapters` |
| `--extract-mode v2` | v2 schema 抽取 | v2 |
| `--model` | 本地模型名 | 取 `settings.json` 的 `llm.model` |
| `--out-dir` | 产物输出目录 | `data/llm_{N}` |
| `--src DIR` | 可视化任务读哪个 LLM 产物目录（如 `cloud_fixed`） | 跟随 `--backend` |
| `--all-outlines` | 全部章纲 | 关 |
| `--characters` / `--settings` / `--summary` | 对应产物开关 | 关 |

> 更完整的接口见各脚本 `--help`。
