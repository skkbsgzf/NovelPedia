# StoryScienceLab 技术文档

> 小说拆书实验工程：把小说正文拆成结构化场景数据（抽取层），再让 LLM 直出章纲/人物/设定/总结（直出层），并用 RAG 支撑问答。
> 本工程同时是 **本地 Ollama vs 云端 dots.ai（小红书 API）** 的对比实验，本文档记录架构设计、schema、性能结论与已知坑。

> 📌 **v1.1 变更（2026-09-01）**：剧情深度推理（暗线收集 `clue_graph` / 剧情推理 / 拉片标注 `scene_annotator` / `stage1_feel` / `main_agent`）已整体迁移至闭源 **studio**，pedia 开源仓不再保留；Stage1/Stage2 均为**三维**（设定/人物/文风 + 实体注册表/最简章纲），并新增**可插拔模块重跑**（`--only`/`--force`/`module_manifest.json`）与**持久 token 计量**（`logs/token_total.json`）。本文档旧章节中涉及暗线/annotate 的部分均为 v1.0 时代记录，仅供参考。

---

## 1. 总体架构

```
小说.txt ─► [抽取层] 切分+抽取 ─► SQLite (395 场景)
                │
                ▼
        [直出层] LLM 直出 ─► outlines / characters / settings / summary (JSON)
                │
                ▼
        [RAG] bge-m3 向量 + FTS5 ─► llm_client ─► 问答
```

**设计原则**：
- **抽取层只做「原子化」**：把正文切成场景块，抽成结构化 actinfo，不做跨章推理。
- **直出层直出**：不做显式归并表，让 LLM 直接输出以「人/事物」为单位的产物，靠模型能力自动完成身份链指（如 周明瑞=克莱恩·莫雷蒂）。
- **统一 LLM 客户端**：`llm_client.py` 屏蔽本地 Ollama 与 OpenAI 兼容云端差异，默认本地、环境变量切云端。

## 2. 抽取层 · 场景抽取（v2 schema）

### 2.1 切分策略（segment.py）

三层信号 + 大小阈值 + 章节边界：

| 信号 | 示例 | 处理 |
|---|---|---|
| 时间状语 | 入夜 / 次日 / 片刻后 | 断块 |
| 地点状语 | 回到 / 来到 / 走出 | 断块 |
| 场景切换词 | 与此同时 / 同一时刻 / 就在这时 | **断块 + 保护**（后续块只允许向前合并，防止被吞） |
| 对话块收尾 | ≥3 段连续对话后的非对话段 | 断块 |
| 大小规整 | 8–15 段 | 不足并入邻块，超出强制断 |

章节边界是硬边界。切分是**确定性规则**，不依赖模型，免费且可复现。

### 2.2 v2 数据 schema

每个场景块输出：

```json
{
  "who": [{"name": "周明瑞", "role": "主事"}],
  "when": {"story_time": "夜晚", "timeline": "顺叙"},
  "where": "公寓·卧室",
  "actinfo": [
    {"type": "act", "who": "周明瑞", "channel": "feel", "content": "剧烈头痛，怀疑脑溢血"},
    {"type": "act", "who": "周明瑞", "channel": "see", "content": "镜中映出克莱恩·莫雷蒂的面容"},
    {"type": "event", "scope": "*", "content": "绯红满月升起，房间被诡异光照亮"}
  ],
  "notes": "本章结尾作者把死亡预言写进笔记本，暗示主角命运"
}
```

- `who/when/where`：L1 锚点，回答「谁/何时/何地」。
- `actinfo`：**有序事件列表**，是下游推理的核心输入。人物通道 `see/do/hear/say/feel/recall/reason`；客观事件用 `type:"event"` + `scope`（影响范围）。
- `notes`：自由备注安全阀，装不进 actinfo 的补充信息。
- **去重**：同角色同通道最多 2 条；总条数按源长度封顶（`max(2, min(12, src_len//60))`）。token 比从 1.24x 压到 0.58x。

### 2.3 抽取实现（extract.py）

- 本地 Ollama `qwen3:4b/8b`，`format:json` 强制合法 JSON，`think:false` 关闭思维链。
- 失败重试 3 次；缓存断点续跑（`extract_cache_rule_v2_{chapters}.json`）。
- 50 章实测：395 场景 / 395 成功。

## 3. 直出层 · LLM 直出

### 3.1 输入构造

按章把 actinfo 拼成流，**每章加 `===== 第X章 =====` 锚点前缀**——防止模型把 scene_id 误读为章节号。

### 3.2 产物（JSON）

| 产物 | 内容 | 说明 |
|---|---|---|
| `outlines.json` | 每章 { 主线, 情节点[], 出场人物[], 场景[], 伏笔备注 } | dict[chapter_no] |
| `characters.json` | 每人物 { name, aliases[], 身份, 弧光, 关系[] } | 身份链指自动命中 |
| `settings.json` | 每设定 { name, type, description, first_seen, related[] } | 世界观设定 |
| `summary.json` | 全书总结 | |

### 3.3 幻觉防护

- 提示词强制「只基于输入，禁止用训练记忆（本书内容）写」。
- 程序校验：人物名逐条核对（章号 ≤ 上限）、设定 first_seen 章号范围检查。
- `_parse_json` 容错：对象优先 + 数组兜底（settings 常被包成 `{"settings":[...]}`）。

### 3.4 已修复的 bug（重要经验）

1. **`_parse_json` 只认对象**：纯数组 `[{...}]` 被截坏 → settings 永远空。修复：对象优先 + 数组兜底 + dict 内 list 提取。
2. **settings 提示词里的 JSON 示例被 4b 当输出回显**：去掉占位示例，改纯文字字段说明。
3. **`gen_settings` 把单条设定对象的 `related` 列表值当设定**：单条设定被丢。修复：含 `name` 键的 dict 直接收。
4. **模型偶发吐坏 JSON**（如 4b 在 28/45 章）：`_parse_json` 救不回时重试，仍失败标注缺失，不阻塞全书。

## 4. 统一 LLM 客户端（llm_client.py）

**这是全工程最重要的抽象**：4 个调用点（extract/stage2/rag_qa/bench）全部收敛到 `chat(system, user, **opts)`。

| 后端 | 触发 | 协议 | 备注 |
|---|---|---|---|
| ollama（默认） | 不设 `LLM_BACKEND` | `/api/chat` | 保留 `--base` 透传、3 次重试 |
| openai 兼容 | `LLM_BACKEND=openai` | `/v1/chat/completions` | 自动 `num_predict→max_tokens`、`format→response_format` |

环境变量：`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_AUTH_SCHEME`（`bearer` 或 `apikey`）/ `LLM_MODEL`。

**RAG 检索不依赖 LLM**：bge-m3 向量已落库，切云端不重算 embedding。

### 4.1 ⚠️ dots.ai 深度思考 token 虚高（本工程最贵的一课）

- 现象：云端 50 章章纲输出 95,278 tok（本地 4b 仅 14,892），但最终 JSON 长度相当（382 vs 431 字符）。
- 根因：dots.ai 深度思考默认开启；旧代码传顶层 `thinking:false` **无效**，`reasoning_content` 持续产生且**计入 `completion_tokens`**。
- 修复：按官方文档改传 `chat_template_kwargs.enable_thinking:false`。
- 效果：单章输出 2427→328 tok（降 86%），JSON 反而更完整（452 vs 364 字符）。
- **经验**：接任何线上模型，先做「最小输入 → 检查 usage 字段与 reasoning_content」探针，确认思考链可关、计费口径。

### 4.2 限流与错误容错

- dots.ai：RPM=60 / TPM=150 万（按 key 计）；429/5xx 退避重试（MAX_ATTEMPTS=4）。
- `.get` 全链路兜底：云端限流返回错误体（无 choices）不再 KeyError 崩溃。

## 5. RAG

- 索引：FTS5（关键词）+ bge-m3 向量（语义，Ollama `/api/embed`，纯 Python 余弦）。
- 检索：`rag.vector_query` → 取 actinfo 组装上下文 → `llm_client.chat` 生成。
- 提示词策略（压制小模型复述问题）：**「结论：」开头 + 引用章节 + 给输出格式示例 + 禁「首先/用户的问题是」**。
  - 本地 8b：三问全部干净直答。
  - dots.ai：偶发复述（指令遵循不稳定）。
  - 本地 4b：复述最重，不适合问答。
- 已知限制：FTS5 无中文分词器，「头痛」等词 0 命中；向量检索正常。

## 6. 性能结论（2026-08 实测）

### 6.1 输入格式：JSON actinfo vs TXT 原文（单章章纲）

| 方式 | 输入 token | 输出 token | 总耗时 | 速度 |
|---|---|---|---|---|
| TXT→4b | 1,898 | 306 | 11.0s | 91.4 tok/s |
| TXT→8b | 1,904 | 256 | 15.3s | 59.4 tok/s |
| JSON→4b | **1,108** | 213 | 10.4s | 94.7 tok/s |
| JSON→8b | **1,114** | 253 | 14.9s | 60.9 tok/s |

**JSON 省 42% 输入 token**，输出/速度基本不变。

### 6.2 50 章产物：本地 4b vs 云端 dots.ai（修复后）

| 维度 | 本地 qwen3:4b | 云端 dots3-note-prev | 说明 |
|---|---|---|---|
| 章纲 | 48/50 | 50/50 | 4b 在 28/45 章吐坏 JSON |
| 人物 | 20 人 | 30 人 | 链指均命中（周明瑞=克莱恩） |
| 设定 | 7 条 | 102 条 | 云端长上下文优势显著 |
| 输出 token | 14,892 | ~16,400（修复后） | 修复前虚高至 95,278 |
| 成本 | 0 元 | 按量计费 | RPM=60 / TPM=150 万 |

---

## 7. 结论与选型建议

- **日常全量跑** → 本地 4b：零成本、离线、够用；设定稀疏可换 8b。
- **精修设定 / 长上下文总结 / 一次性高质量产物** → 云端 dots.ai：信息密度高，但要控输出 token（关深度思考）。
- **问答** → 本地 8b + 收紧提示词。
- **任何线上模型** → 先探针验证 thinking 开关与计费口径。

## 7.5 可视化层

数据流：`直出层产物(JSON) + 抽取层 db(原文/场景)` → `build_detail.py` → `detail_data.json` → 模板注入 → 自包含 HTML。

| 模块 | 脚本 | 产物 | 要点 |
|---|---|---|---|
| 拆书详情数据 | `build_detail.py` | `detail_data.json` | 四板块结构化数据；供 pedia 内联与二次开发（旧 `book_detail.html` 独立页已废弃） |
| 关系图谱数据 | `export_graph.py` | `graph_data.json` | 节点/边带章节集合；供 pedia 内联（旧 `knowledge_graph.html` 独立页已废弃） |
| 性格六维 | `gen_personality.py` | `personality.json` | dots.ai 分批 5 人/批 + 重试 + 增量缓存；支持 `--src` |
| 归档 | `cli.py viz` | `outputs/<小说名>_<日期>/index.html` | pedia 主页面（自包含，内嵌上述全部数据） |
| 健康检查 | `check_viz.py`（已归档） | 控制台 | 数据/模板一致性断言；已移入 `archive/novel_pipeline_死代码_20260901/` |

**detail_data.json 结构**：
```
book / chapters(50) / timeline(167事件) / outlines(章纲+伏笔) / tags(三色浮点)
characters(画像+dims六维) / charGraph(23节点65边, 别名归并后) / settings(4分类55条)
style(全书文风) / perChStyle(每章文风, 词带 pct)
```

**关键实现**：
- **别名归并**（`vizutil.merge_alias_components`）：直出层 LLM 常把同一人拆成多条
  （周明瑞/克莱恩·莫雷蒂、邓恩/邓恩·史密斯/马车夫）。用 `aliases` 字段建无向图求连通分量，
  按（别名度数, 名字长度, 首次出现章）选主名，30→23 人。纯数据驱动、确定性，不重跑 LLM。
- 浮点标签：绿=characters.首次出现章、蓝=settings.first_seen、橙=outlines.场景去重首见
- 人物图谱边：显式关系从 characters.关系 解析（`名称：描述`，别名归一）；共现从 scenes.who_json 构建（≥2 次才建边控密度）
- 文风统计：jieba 分词（去停用词）+ 句长按 `。！？；` 切分 + 标点/句式正则（反问/感叹/排比/比喻规则粗判）；
  每章独立统计支撑章节筛选。**无 jieba 的环境用 2-4 字滑窗 + 子串去重兜底（纯标准库）**；
  "排比"已剔除「一个…一个…」类枚举式（原误报率 37% → ~14%），仍为近似值，仅作风格参考
- 前端零依赖：力导向/雷达图/柱状图/词云全部手写 SVG/CSS

**SVG 渲染经验（白屏坑）**：
1. `<g>` 分组必须用 `createElementNS('http://www.w3.org/2000/svg','g')`，混 HTML 命名空间 → paint 区域 0×0
2. 顶层 `let` 声明必须先于初始化调用（TDZ），否则 `Cannot access X before initialization`
3. headless `--screenshot` 不渲染 SVG 填充，验证须用 CDP 真实 paint + `getBoundingClientRect()` 检查

### 7.6 拆书知识库面板（Wikipedia 式, index_template.html）

Stage1 直出产物 → `cli.archive_stage3()` 注入 → **自包含 `outputs/<书>_<日期>/index.html`**（零依赖, 浏览器直开）。
与传统 Tab 工作台（book_detail.html）并存的**新一代主入口**, Wikipedia 词条式布局:

```
顶栏(全局搜索+计数) / 左侧目录树(导航+人物+设定分类) / 主区(面包屑+词条正文+右侧 Infobox)
```

**视图**: 概览(核心词条榜/设定体系/全量图谱) / 人物简历页 / 设定词条页 / 剧情推理 / 文风分析。

**注入通道（cli.py → 模板占位符）**:
`DETAIL/GRAPH/PERSONALITY/FEELINGS/CLUE(剥vector)/STYLE/RESUMES/SETTINGS_SYSTEM/SETTINGS_GRAPH(508词条+322关系, 剥vector)/CHAR_FACTS(语录行为)/ENTITY_REG(别名)/GENERIC_LEXICON(公版词库)`。

**核心机制**:
- **整合度权重**（解决"整合度高的词条排前面"）:
  `weight = 40·log10(1+暗线occurrence) + 25·log10(1+场景数) + 20·log10(1+关系度[relations+related]) + 15·被结论引用`
  原始分排序(保区分度), 显示 `fmtW()` 封顶 100。分级 **S≥60 / A≥35 / B≥15 / C<15**;
  侧栏按权重降序 + 色点标级, C 级折叠"▸ N 个次要词条"。阈值在 `termWeight()/lvlOf()` 内, 换书可调。
- **内链**: 全部人物名+设定名构建一个长正则(按名字长度降序防子串误吞), 正文自动高亮为可点链接, 不创造新实体。
- **防幻觉来源徽章**: 每个字段标注 来源 —— 绿=原文抽取 / 黄=LLM推断(身份/履历/性格/疑点) / 蓝=统计聚合 / 紫=混合。
  面板本身零生成, 全部字段来自 stage1 JSON。
- **Infobox**: 人物页=小圆头像; 设定页=**局部一跳关系小图**(`drawMiniGraph`, 268×124→半屏 430×260)。
  SVG 高度用 `svg.clientHeight`（曾硬编码 440 导致小图溢出）。
- **渲染容错**: `go()` 内 renderMain/renderSide/图谱绘制各自 try/catch, 单模块失败不拖垮整页。

**踩坑记录**:
1. `archive_stage3()` 内 `s1_dir = s1_dir` 自赋值 → `UnboundLocalError`, 改为 `s1_dir = C.STAGE1_DIR`（现在可独立重建 index.html, 不必重跑 LLM）。
2. `forceLayout` 中 `const focus` 声明在 `nodes.forEach` 引用点之后 → TDZ 中断图谱+侧栏。
3. 验证方法: Edge CDP(`--headless=new` + remote-debugging-port) 真机渲染, 捕获 `Runtime.exceptionThrown` + 检查 SVG 实际绘制面积; 脚本 `_verify_cdp.py` 可复用。

### 7.7 公版通用名词词库（generic_lexicon.json, 跨书共享资产）

**动机**: "医院/诊所/队友/敌人"这类放在任何小说里都成立的通用概念没有记录意义, 混进设定图谱污染词条。判定标准: **一个词放在别的小说里同样成立, 就不收**。

**单一资产, 两端消费**:
| 端 | 用法 | 时机 |
|---|---|---|
| pipeline(`setting_agent.py`) | `load_lexicon()` + `is_generic_name()`, `convolve_settings` **入口拦截**, 通用词根本不入图谱 | 抽取时(治本) |
| 面板(`cli.py`注入`__GENERIC_LEXICON__` → 模板) | `isGeneric()` 打标: 灰显+黄点, 侧栏【本书设定/含通用】开关, Infobox 警示条 | 展示时(对旧产物兜底) |

**词库结构**: `categories`(地点设施/关系群体/物品装备/时间概念 ~90词) + `patterns`(`^[SABCDEF]级`、`^\d+(分|点|枚|张)$`、`^\d+$`) + `protected.prefixes`(《【 包裹视为专有) + `notable_exceptions`(牧师/信徒为何刻意不收, 防后人误加)。

**维护**: 直接往 `categories` 加词; 降级安全——文件缺失时 pipeline 打警告但不阻塞。设计取舍: 职业名(牧师/法师)与群体词(信徒)不进词典, 因具体书中常有特指, 误杀代价高于漏杀, 交给抽取 prompt 约束(`SET_USER` 已加"只收本书专有名词"硬规则, 与词库双保险)。

**回归用例**(10/10 通过): 医院/队友/2000分/S级天赋=拦截; 觐见之梯/《SCIENCE》/圣光医院/生命の信仰/接生宫锯=保留。

### 7.8 网文设定体系「图 RAG」（webnovel_lexicon.py + webnovel_lexicon.json）

**定位**: 作用于**整个 pipeline** 的公版正向知识库, 以**图**形式存在并支持高效检索/补全/丢弃;
与 §7.7 的负向停用词互补, 并与**本文知识库**(settings_graph / clue_graph) 双向关联。

**三库分工**:
| 库 | 方向 | 作用 |
|---|---|---|
| `generic_lexicon.json` | 负向 | 通用词"及时扔掉"(不入图谱) |
| `webnovel_lexicon.json` | 正向·公版 | 网文体系骨架(跨书共享), 图 RAG 检索 + 补档 + 跨书迁移 |
| 本文 settings_graph | 正向·实例 | 本书实际设定, 通过 `wn_domain/wn_slot/wn_rank` 挂到公版图 |

**图结构**(加载时从词表**派生**, 改词表即改图, 不维护两份数据):
- node = 体系词条(炼气/斗帝/序列9/主神空间…), 带 `domain`(域) + `slot`(槽位) + `rank`(等级序号)
- edge = `next_level`(同体系相邻等级, 有向) / `in_domain`(域内归属) / `aligned_with`(跨体系对齐, 跨书迁移的真边)
- 实测: **438 节点 / 423 词条 / 504 边**(in_domain 423 · next_level 62 · aligned_with 19), 15 个域

**四个核心 API**:
| API | 用途 | 备注 |
|---|---|---|
| `search(q, topk, embed_fn)` | 高效匹配: 精确→前缀→子串→**编辑距离≤1**(纯标准库, 覆盖"练气/炼气"形近错字)→可选 embedding 语义 | 零 LLM 成本 |
| `match_terms(names)` / `annotate_terms(terms)` | 批量把本文词条映射到公版节点, 就地写 `wn_*` 字段(幂等) | **双库互链** |
| `suggest_missing(book_terms)` | 公版序列 vs 本文已有 → 找**中间缺档** | "快速补全" |
| `neighbors(name, hops)` | 图上 n 跳扩展, RAG 召回时带上体系上下文 | 跨体系对齐可达 |

**pipeline 接入点**:
1. `setting_agent.convolve_settings`: 通用词拦截(§7.7) + 公版体系打标(零 LLM 成本)
2. `cli.archive_stage3`: 对已有产物补打标(幂等) + 注入面板(词表映射 + 补档建议)
3. 面板: 词条页 Infobox「网文体系」行(域/槽位/档位); 概览页「体系补档建议」卡
4. 未来: 抽取 prompt 注入领域参考词表; RAG 问答把体系上下文一起召回

**效果实测**:
| 书 | 体系 | 命中率 |
|---|---|---|
| 诡秘之主(序列/克苏鲁) | 真实设定词 20 个 | **17 命中(85%)**, 档位正确(序列9=第1档) |
| 斗破苍穹(斗气) | 真实设定词 10 个 | **9 命中**(斗帝=第10档) |
| 诸神愚戏(信仰游戏·自创体系) | 508 词条 | 4 命中(合理: 自创体系词多) |

- **补档**: 本文只抽到[序列9, 序列5] → 提示缺 `序列8/7/6`; [斗者, 斗宗] → 缺 `斗师/大斗师/斗灵/斗王/斗皇`
- **跨书迁移**: `序列5 ↔ 元婴(修真) ↔ 斗宗(斗气)` 在图上是真实 `aligned_with` 边, 可一跳到达

**维护**: 往 `domains.<域>.<槽位>` 加词; 收录标准是**网文圈读者看到即懂的体系骨架词**, 不收单一作品专名
(如"焚决""大衍诀"是某本书的专有设定, 不属于公版体系)。`slot_meta` 声明槽位是否有序(决定能否补档)。

### 7.9 起止位置标注（span）与 global/local 知识库加载策略

#### 7.9.1 起止位置盘点（2026-08-29 实测，诸神愚戏 20 章产物）

| 层 | 起点 | 止点 | 结论 |
|---|---|---|---|
| 设定词条 `settings_graph.terms` | `first_seen` **508/508** ✅ | **0/508** ❌ | **原本只有起点无止点**，末次需从 `source_scenes` 反推 |
| 暗线证据 `clue_graph.evidence` | `chapter_no`+`scene_id` 455/455 ✅ | `last_seen` 455/455 ✅ | 最完整（还有 `occurrence` / `status` / `refuted_by`） |
| 暗线实体 `clue_graph.entities` | — | `last_seen`+`occurrence`+`count` 216/216 ✅ | 止点语义=最近一次出现（记忆衰减用） |
| 人物简历 `characters_resume` | `appearances[[ch,scene]]` 可算 | 同（可算） | 无独立字段，每次现算 |
| 人物事实 `character_facts` | sayings 内嵌 `"第X章sceneY"` 字符串 | 同 | **非结构化**，无法直接检索/筛选 |

**三个问题**：①设定词条缺止点（而记忆衰减/归档判定恰恰需要它）；②人物层起止要现算；③sayings 定位是字符串内嵌。

**已修复**：`setting_agent.convolve_settings` 内每次出现覆盖 `term["last_seen"] = chapter`，卷积结束即为"最后一次出现在第几章"（增量维护，无需查 db）。实测：同一词条在第 5/12/20 章出现 → `first_seen=5, last_seen=20` ✅

**统一规范**：`pedia_schema.json → span`（各层必填）
```
span = {first_chapter, last_chapter, first_scene, last_scene, scene_count, chapter_count}
```
填充规则写在 schema 的 `span.how_to_fill`（世界观取 first/last_seen；人物取 min/max(appearances[0])；剧情取簇内最大 chapter_no）。
止点语义 = **最后一次出现**，与 `clue_graph.entities.last_seen` 一致，**不是"失效"**。

#### 7.9.2 global / local 知识库加载策略

**原则**：global 通识库**默认不对外开放**；只在必要时按类别加载；**仅供参考，与原文冲突一律以本次阅读到的为准**。

| 库 | 默认 | 何时加载 | 作用 |
|---|---|---|---|
| **local**（本文 settings_graph / clue_graph / resume） | 始终 | 每次运行 | 事实来源，优先级最高 |
| **global**（webnovel_lexicon 通识体系库） | **关闭** | 显式 `--genre` 或先搜索判定类别后 | 补档/分类/候选参考，**不覆盖本文事实** |

**实现**（`webnovel_lexicon.set_scope`）：作用域未开启时 `lookup_term/search/match_terms` 一律返回空，pipeline 完全不受 global 影响；指定域后仅该域生效（域隔离，避免修真知识污染宫斗书）。

**用法**：
```bash
python src/cli.py collect --genre 宫斗      # 只加载"宫廷权谋"域
python src/cli.py collect --genre 修仙      # 只加载"修真仙侠"域
python src/cli.py collect                   # 不加载(默认)
```
透传链路：`cli --genre` → `resolve_genre`(别名→域) → `env NOVEL_GENRE` → 子进程 `setting_agent._auto_scope_from_env()` 自动生效。

**"先搜索查类别"**：`webnovel_lexicon.detect_genre(sample_names)` 用本书样本词条临时全域检索，统计各域命中数返回候选（如 `[诡秘神秘学×4, 修真仙侠×2]`），**只判定不改作用域**，判定完仍需显式加载。

**域覆盖**（18 域 / 551 词 / 644 边）：修真仙侠·武侠国术·玄幻斗气·高武全球·系统流·无限流·诡秘神秘学·SCP收容·规则怪谈·洪荒流·都市异能·游戏电竞·科幻机甲末世·历史军事争霸·**宫廷权谋**·**宅斗种田**·**恐怖灵异**·剧情桥段套路。
（后三个为本次补齐——此前宫斗/宫廷、宅斗种田、恐怖灵异**全部缺失**。`genre_aliases` 提供 35 条口语别名：宫斗→宫廷权谋、修仙→修真仙侠、灵异→恐怖灵异…）

**优先级铁律**：global 命中只写 `wn_domain/wn_slot/wn_rank` 元数据，**绝不覆盖**本文抽到的 `definition`/`category`。
