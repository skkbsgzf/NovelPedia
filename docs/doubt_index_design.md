# 质疑指数 (doubt_index) 设计文档

## 概述 (v3 · 证据收集 → 图谱整合 → 批量推理)

`doubt_index` 是 0-1 的参数，控制主agent的**杠精属性**——决定**证据簇积累多少才触发批量推理**、推理做多做少。**它是连续旋钮，不是开关**。

### v3 核心架构（对应讨论结论）

```
Stage1a 证据收集(每场景一次轻量 LLM):  只输出「事实池」——原文摘录+涉及实体
                                       0 推理、0 判断、token 硬上限(注意力预算)
Stage1b 图谱整合(零 LLM):              证据 bge-m3 向量化 → 增量聚类
                                       语义相近自动归簇(接生工具≈宫锯 自动归一)
                                       → clue_graph.json(证据/簇/实体)
Stage1c 批量推理(簇权重触发):          簇权重达阈值 → 一次 LLM 调用出多条结论
                                       (fact/reason/hypothesis/chain + 引用证据ID)
Stage3 可视化:                         结论卡片 → 展开推理链(结论→证据簇→原文)
                                       + 线索图谱(结论红/簇橙/证据绿)
文风(独立):                            style_sampler 全文随机采样10%, 长句:短句=7:3
                                       一次性统合分析, 与线索图谱流程完全分离
```

**设计动机**（用户讨论结论）：
- 初读**只收集 evidence**（轻量事实池），不逐场景推理——消除冗余与过度解读
- 推理攒到**阶段性阈值**一次性批量做，一次调用出多条结论（类比 setting_agent 的"收集词→图谱→向量"哲学）
- **无用证据不在图谱内**（孤立、低关联）不参与推理，也不进可视化
- 向量聚类天然解决别名问题（"接生工具"与"宫锯"同簇），这是字符串聚类做不到的

### 向量聚类阈值（实测校准 0.5）

bge-m3 对短事实句的余弦相似度：同主题/相关主题 0.51-0.70，不同主题 0.31-0.38。
取 0.5 为聚类边界：相关证据归簇，无关证据分离。

### doubt_index 的连续调节 (v3)

| doubt_index | 簇触发阈值(证据数) | chain 深度 | 证据token预算 | 适用 |
|---|---|---|---|---|
| 0.3 | 6 | 2 句 | 300 | 普通网文(快, 只推主线) |
| 0.5 (默认) | 4 | 3 句 | 400 | 一般小说 |
| 0.7 | 3 | 4 句 | 400 | 悬疑/考据 |
| 0.9 | 2 | 4 句+多假设 | 500 | 硬核推理(见异常就杠) |

低指数 = 证据攒得多才推理、chain 短、token 预算小（快）；高指数 = 见异常就推理（慢但深）。阈值连续线性插值。

### 输出文件

- `stage1/clue_graph.json` — 线索图谱(evidence/clusters/conclusions/entities)
- `stage1/reader_feelings.json` — 结论(疑点) + 文风分析(引用证据ID)
- `stage1/style_analysis.json` — 文风采样分析(独立)
- `stage1/settings_map.json` / `settings_graph.json` — 设定子agent(不变)

## (v2 架构, 已废弃) 线索积累 → 阈值触发 → 统合推理

> 旧版按主题字符串聚类(clue_topics), 逐主题单独推理。问题: ① 字符串聚类抓不到别名("接生工具"≠"宫锯"); ② 一次调用只出一条结论, 碎且慢。已废弃, 改为 v3 的向量聚类+批量推理。

## (v1 架构, 已废弃) 每场景立即解读

> 旧版每场景立即深度解读。问题: ① 同场景重复; ② 文风套话; ③ chain 模板; ④ 每场景高深度拖慢速度。已废弃。

### 解决的三个问题

1. **无重复、精选**：疑点只在"线索够多"时生成，同一主题全书一条，后续线索挂到其下（followups/evidence），不再"每场景都记一条"
2. **文风深入**：手法实例轻量积累，攒够后统合分析文风体系（手法库+意象+节奏），而非逐场景"淋漓尽致"
3. **CoT 有据可依**：chain 基于真实积累的线索链推理，每条疑点带 `evidence: [场景列表]`，可可视化"疑点怎么从 N 处线索长出来的"

## 知识库归档（长文本边际爆炸防护）

参考调研《长文本知识库归档_SOTA》(MemGPT/Graphiti/SCM/BIRCH)。解决 200+ 章下
"证据只增不减 / prompt 注入膨胀 / 聚类 O(n²)" 三个缺口。

### 核心机制

```
证据/实体带记忆字段:  last_seen(章号) / occurrence(次数) / status(active|archived|refuted) / refuted_by
活跃层过滤:          推理/注入只喂活跃簇(四条件 OR, 长程伏笔保护)
代际压缩 consolidate: mine 前执行, 过期低频证据 → archived(文件保留, 不参与计算)
```

### 活跃判定（四条件 OR）

```python
active = recent(Δ≤w_recent章) OR frequent(权重≥k_freq) OR weighted(≥4) OR confirmed(≥k_confirm)
```

OR 条件防误杀长程伏笔：ch1 埋的线 ch500 才收，只要被证实过 2 次或权重高就保持活跃。

### 参数配置（settings.json run.archive，非硬编码）

| 参数 | 默认 | 含义 |
|---|---|---|
| `w_recent` | 30 | 最近 N 章出现过 → 活跃 |
| `k_freq` | 3 | 在 ≥N 章出现 → 活跃(非噪声) |
| `k_confirm` | 2 | 被后文证实 N 次 → 永久活跃(长程伏笔保护) |
| `every` | 20 | 每 N 章做一次代际压缩(mine 前) |

`w_recent=30` 依据：网文单卷/大弧约 30–50 章。20 章内归档不触发是**正确的**
（30 章窗口覆盖全部）——机制为 200+ 章设计。

### 向后兼容

旧 clue_graph 无 last_seen/confidence → 不误归档、不误过滤（`has_conf` 检测）。

### 待办（P2）

- BIRCH 式增量聚类：新证据只与簇质心比，O(n²)→O(簇数)
- 证伪深化：结论级矛盾覆盖（当前仅实体级属性覆盖）

## (v1 设计, 已废弃) 旧方案：每场景立即解读

> 旧方案是"每个场景立即让 LLM 深度解读并输出疑点"，问题：① 同场景两条疑点指向同一事实却因措辞不同不被去重；② 文风输出套话；③ chain 是模板。已废弃，改为上面的线索积累架构。

## 影响范围 (v1 保留参考)

### 1. FEEL_USER 思考深度

根据 `doubt_index` 动态调整提示词指令：

- `doubt_index < 0.4`：浅层阅读，只关注剧情和表层感受
- `doubt_index 0.4-0.6`：中等深度，关注信息差和反常
- `doubt_index > 0.6`：深层阅读，强制要求：
  - 跨场景追踪（track: true）
  - 挖掘前后矛盾
  - 识别身份存疑
  - 提取隐藏动机

### 2. 疑点数量上限

```python
MAX_DOUBTS_PER_SCENE = 1 if doubt_index < 0.4 else 2 if doubt_index < 0.7 else 3
```

### 3. Cross-scene Tracking

- `doubt_index < 0.4`：不启用 track（不跨场景比较）
- `doubt_index >= 0.4`：启用 track，优先标记信息差/矛盾点
- `doubt_index >= 0.7`：强制 track（track: true）

### 4. 名词查询上下文数量

- `doubt_index < 0.4`：max_ctx=2（快速查定义）
- `doubt_index >= 0.4`：max_ctx=4（收集更多上下文）
- `doubt_index >= 0.7`：max_ctx=6（深度理解）

### 5. 思维链输出

每个感受（entry）包含 `chain` 字段，存储 LLM 的思维过程：

```json
{
  "type": "疑点",
  "raw": "医生虽然被孕妇多次呼唤...",
  "chain": "1. 检测到医生反应慢与接生紧急情况矛盾\n2. 前文未提及医生真实身份\n3. 结合孕妇的异常表现\n4. 推断：医生可能非真医生，存在信息差\n5. 结论：标记为疑点，跨场景追踪",
  "track": "true"
}
```

## 思维链可视化方案

### 方案 A：前端 UI 展示（推荐）

在 stage3 的可视化界面中，点击一个感受时，展示其思维链：

```
┌─────────────────────────────────────────┐
│ 感受类型：疑点                           │
│ 原始内容：医生虽然被孕妇多次呼唤...      │
│ ──────────────────────────────────────  │
│ 思维链：                                 │
│ 1. 检测到医生反应慢与接生紧急情况矛盾   │
│ 2. 前文未提及医生真实身份               │
│ 3. 结合孕妇的异常表现                   │
│ 4. 推断：医生可能非真医生，存在信息差   │
│ 5. 结论：标记为疑点，跨场景追踪          │
│ ──────────────────────────────────────  │
│ 跨场景追踪：[场景1] → [场景5]           │
└─────────────────────────────────────────┘
```

### 方案 B：JSON 字段存储

在 `reader_feelings.json` 中：

```json
{
  "entries": [
    {
      "type": "疑点",
      "raw": "...",
      "chain": "1. ...",
      "track": true
    }
  ]
}
```

前端读取 `chain` 字段并渲染。

### 方案 C：独立思维链文件

生成 `reader_chains.json`，包含所有思维链：

```json
{
  "schema": 1,
  "entries": [
    {
      "scene_id": 1,
      "chapter_no": 1,
      "chain": "..."
    }
  ]
}
```

前端按 scene_id 关联到感受。

### 2. 前端四个可视化层

| 层 | 内容 | 交互 |
|----|------|------|

### 2.5 思维链质量约束（已修）

初次实现时 LLM 把 `chain` 字段的格式模板（"1. 观察→2. 前文对比→3. 推断→4. 结论"）当成输出直接复制，
全部 chain 变成同一句话。修复：

- 提示词**不再给出流程标签格式**，改为给出具体示例（如「医生做接生手术却用钢锯, 这不合常规; 前文他自称是医生, 但全程没有行医细节; 所以我怀疑他身份有问题, 这个疑点值得追踪」）
- 明确**禁止写"观察/推断/结论"这类流程标签**, 禁止照抄格式模板
- chain 要求 2-4 句真实思考, 结合本场景具体事实

### 3. 思维链展示细节

- `chain` 字段按换行拆分成步骤，每步 `▸ 步骤内容` 渲染，保留推理过程可读性
- 卡片未展开时只显示"💭 思维链"角标，不占版面
- 疑点卡片若 `track=true` 显示 ⭐ 追踪标记，便于筛选可回看线索

### 4. 后续可扩展的可视化方向

- **疑点 → 揭晓连线图**：reader_memory.json 的 puzzles(status: open→resolved) 与揭晓场景连线，展示"读者带着疑问读，被揭晓时解答"
- **跨场景追踪线**：同一疑点多次 track 出现的场景位置，连成时间线
- **思维链词云**：统计各 step 的高频推理动词（观察/对比/推断/结论）
- **doubt_index 对比视图**：同一作品不同 doubt_index 跑两遍，对比疑点质量与密度
