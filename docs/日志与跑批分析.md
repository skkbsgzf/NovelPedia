# 日志与跑批分析（常态化）

> 跑批日志基础设施 `src/logbook.py` + 分析命令 `cli analyze` + 文档（本文）。
> 目标：每次跑批留下**结构化、可分析、可对比**的日志，跑完一条命令出健康报告。

---

## 1. 架构一页

```
collect / mine / extract / ...
   └─ logbook.py(统一日志器, 线程安全)
        ├─ 人类可读 → logs/run_<时间戳>.log      ← 控制台同款, 直接看
        ├─ 结构化   → logs/run_<时间戳>.jsonl    ← 程序分析
        └─ 最近会话 → logs/run_latest.jsonl       ← cli analyze 默认读这个

cli analyze [--log 路径]  →  跑批健康报告(阶段/错误/进度/指标曲线/健康度)
```

**日志统一规则**：
- 每条约 `[时间] [step] [级别] 消息 {结构化字段}`
- step：`collect / mine / setting / clue / char / style / extract / logbook …`
- 级别：`DEBUG / INFO / WARN / ERROR`
- 结构化字段进 jsonl（可程序化聚合），人类读 log 时附在行尾

## 2. 日志格式示例

人类可读 `.log`：
```
[10:46:44] [collect] [INFO] ============
  Stage1 收集 · 300 章 / 2452 场景
============
[10:46:44] [collect] [INFO] 开始 scenes=2452 chapters=300 doubt_index=0.5 parallel=4
[10:46:44] [setting] [INFO] 设定抽取统计 scenes=2452 ok=1830 empty=622 empty_rate=25.4 elapsed=3600.5
[10:46:44] [gauge:setting] [INFO] terms=119 chapter=50
[10:46:44] [clue] [INFO] 进度 1200/2452 (48.9%) 已用 32m ETA 1h33m terms=119
```

结构化 `.jsonl`（每行一条）：
```json
{"ts":"2026-08-29T10:46:44","level":"INFO","step":"setting","msg":"设定抽取统计",
 "scenes":2452,"ok":1830,"empty":622,"empty_rate":25.4,"elapsed":3600.5}
```

## 3. 常态工作流

```bash
# 1) 跑批(collect/mine 自动写日志)
python src/cli.py collect --chapters 300 --backend xiaohongshu
python src/cli.py mine   --chapters 300 --backend xiaohongshu

# 2) 跑完即分析(默认读最近一次会话)
python src/cli.py analyze

# 3) 对比历史会话
python src/cli.py analyze --log logs/run_20260829_060309.jsonl
```

## 4. 健康度指标（analyze 自动检查）

| 编号 | 指标 | 正常区间 | 异常含义 | 对应缺陷 |
|---|---|---|---|---|
| H1 | 设定抽取失败率 empty_rate | < 15% | key 失效/限流/prompt 崩 → 词条大量缺失 | D1 |
| H2 | 设定词条数 terms | ≥ 章节数 | 增量复用/抽取未覆盖全书 | D1 |
| H3 | 推理覆盖 (结论/达标簇) | > 30% | mine 中断/阈值过高 | D3 |
| H4 | 设定碎片率(单场景词条占比) | < 50% | 抽取碎片化, 图谱无结构 | D2 |
| H5 | 单例簇占比 | < 40% | 证据碎片化 | D8 |

> H4/H5 需结合产物统计（`_audit_gm.py` 思路），日志层主要给 H1-H3 和进度/耗时。

## 5. 进度与 ETA（跑批中实时看）

collect 的设定抽取（串行）每 200 场景、卷积每 25 章输出进度：
```
[setting] 进度 1200/2452 (48.9%) 已用 32m ETA 1h33m terms=119
```
- 已用 = 阶段累计耗时；ETA = 按当前速度推算
- `terms=119` 即"当前图谱规模" → 跑批中途即可判断词条增长是否正常（前 50 章应已有几十词条，若一直个位数就是抽取异常）

## 6. 指标曲线（analyze 输出）

`gauge:setting terms chapter=50` 这种带 chapter 的指标，analyze 按章排序输出：
```
【指标·setting】
    第50章: terms=41
    第100章: terms=78
    ...
```
→ 直接看出"设定词条随章节增长曲线"，异常时一眼定位（如前 300 章只到 119 即 D1）。

## 7. 排障速查

| 现象 | 查什么 | 位置 |
|---|---|---|
| 词条数异常少 | `[setting] 设定抽取统计` 的 empty_rate | log |
| 中途停止 | 最后一条进度时间戳与 ERROR | jsonl 按 ts 排序 |
| 推理少 | `[mine] consolidate` 的 new_conclusions/total | log |
| 限流/超时 | ERROR 记录的 err 字段（timeout/429） | jsonl 过滤 level=ERROR |
| 与上次对比 | 两个会话的 jsonl 分别 analyze | --log |

## 9. 常用命令备忘

```bash
# 实时看当前跑批日志
tail -f logs/run_latest.log          # 人类可读
tail -f logs/run_latest.jsonl        # 结构化

# 分析最近一次
python src/cli.py analyze

# 分析指定会话
python src/cli.py analyze --log logs/run_<时间戳>.jsonl

# 清日志(按需)
rm logs/run_*.log logs/run_*.jsonl
```
